**Real Map Implementation of Greedy Best-First**

Ever wondered how navigation apps find a path? This visualization showcases the Greedy Best-First algorithm, a fascinating approach to pathfinding. Unlike algorithms like Dijkstra's or A*, Greedy Best-First prioritizes exploring nodes that appear *closest* to the target. It uses a **priority queue** to store its candidate nodes, but the priority is solely determined by a heuristic function (in this case, the straight-line distance or Euclidean distance) to the goal. It greedily expands the node that it *believes* will lead it to the target fastest, without considering the cost of the path taken so far. This makes it exceptionally quick for initial exploration, but it can sometimes lead to suboptimal or even incorrect paths if it gets "stuck" in a locally good-looking but globally poor route.

In this "Real Map Implementation," we've transformed the charming streets of Lisbon's Belém district into a graph. Each **intersection** is a node, and each **street segment connecting two intersections** is an edge. The red and green lines you see represent the **visited edges** as the algorithm explores potential routes. The vibrant yellow line highlights the **computed path** generated by Greedy Best-First from start to finish. It's crucial to note that real-world road networks introduce complexities beyond simple grids. Street layouts are irregular, intersections might have varying numbers of outgoing roads, and one-way streets add directional constraints. These factors make graph representation and traversal algorithms like Greedy Best-First essential tools for efficient navigation.
